# Шаг 4: реакция на поток и текущая скорость

Тест нуля подтверждён пользователем. Новый цикл: связь → ноль 10 с → «Дуйте в трубку». На этапе потока экран показывает текущую расчётную скорость, оставшееся время и общий спиннер. Отсчёт начинается после первого полного вывода инструкции. Обновление по страницам с приоритетом опроса сохранено.

## Настройки

| Параметр | По умолчанию | Назначение |
|---|---|---|
| kFlowWaitMs | 10000 мс | Время ожидания реакции |
| kFlowSamplePeriodUs | 20000 мкс | Опрос потока 50 Гц |
| kFlowHoldMs | 100 мс | Короткое подтверждение выдоха, после которого событие запоминается |
| kFlowMinimumMs | 4000 мс | Минимальная длительность экрана «Дуйте» |
| kFlowThresholdPa | 50 Па | Порог относительно нуля предыдущего этапа |
| kFlowAllowNegative | true | Реакция в обе стороны; false — только положительная |
| kAirDensityKgM3 | 1,225 кг/м³ | Принятая плотность воздуха |
| kSpeedZeroBandPa | 3 Па | Зона нулевой скорости только для отображения |
| kSpeedInKmh | false | false — м/с, true — км/ч |

Начальные значения ожидания, удержания и порога выбраны для первого аппаратного прогона; они не являются заводскими критериями исправности. Все настройки находятся в начале скетча. После успешного нуля его значение остаётся фиксированным.

Скорость вычисляется как sqrt(2*abs(давление−ноль)/плотность), выводится с одним десятичным знаком. Это оценка по давлению, не измеренная эталоном скорость потока. Зона нуля не влияет на обнаружение реакции. При разрешённой отрицательной реакции перепутанное направление трубок не проверяется; знак давления остаётся доступным в Serial. Скорость на экране — модуль.

Порог должен удерживаться не менее 100 мс подряд (несколько отсчётов при 50 Гц): до подтверждения при падении ниже порога накопление времени сбрасывается. После подтверждения событие фиксируется независимо от текущего давления, на экране «Принято». Переход разрешён не раньше 4000 мс после начала этапа, чтобы оператор успел увидеть скорость. Можно коротко дунуть в начале и прекратить: попадать на конец этапа не требуется. Возврат всё равно проверяется отдельно и требует непрерывной выдержки 1 секунду. Если за 10 секунд ни одного подтверждённого выдоха нет — общий экран «БРАК / Нет реакции». Любая ошибка чтения либо расписания также немедленно останавливает этот этап. Диагностический режим связи не отменяет остановку на последующих этапах.

После успешной реакции автоматически запускается проверка возврата к нулю: step5-return.md. Заглушка удалена.

По замечанию пользователя экран потока переработан: одна строка «Дуйте» сверху, спиннер в отдельной зоне справа; скорость по центру с базовой линией 40, ниже разделитель и таймер с базовой линией 61. Прежняя вторая строка подсказки убрана, чтобы увеличить интервалы между элементами. Новый макет ожидает визуальной проверки на экране.

## Память и журнал

Чтобы поместить этап в Nano, kDiagnoseI2cOnFailure и kDetailedSerialLog выключены по умолчанию. Краткий LINK сохраняет состояние, последнюю/первую ошибку, режим, успешные чтения, попытки, пропуски и количество ошибок. Сборочные параметры расширенной диагностики остаются в начале, но при включении необходимо заново проверить вместимость Flash. Основная логика проверки связи не ослаблена.

BOOT: wing-tester return-v2. FLOW содержит passed, n, confirmed, dp_pa (последний перепад относительно фиксированного нуля), peak_pa (максимальный модуль перепада). При провале FLOW_FAIL reason; при ошибке чтения READ error/status/rx.

В аппаратном журнале пользователя связь прошла 100/100, ноль прошёл 500 отсчётов, а поток не прошёл при peak_pa=395,39 и конечном dp_pa=0,85. Пик подтверждает изменение показаний, но не доказывает прежнюю непрерывную выдержку 1 секунду. По запросу пользователя выдержка сокращена до 100 мс, защёлка подтверждения выделена в updateLatched(). Проверка «ранний выдох, затем ноль до конца» и одиночный выброс прошли compile-time тесты. Новая сборка: Flash 29354 байт (95%), глобальная RAM 1090 байт (53%). Аппаратное подтверждение новой логики ожидается.

Сборка Nano ATmega328P успешна: Flash 28646/30720 байт (93%), глобальная RAM 1072/2048 байт (52%). Детектор удержания проверен AVR-компилятором через static_assert: устойчивый поток, одиночный всплеск, прерывание потока, отсутствие реакции и переполнение счётчика времени. Аппаратный результат ещё не получен.

## Аппаратная проверка

1. Загрузить скетч; во время связи и проверки нуля не подавать поток.
2. Только после «Дуйте» подать поток в трубку Пито: скорость должна измениться, устойчивая реакция переводит к «Не дуйте» не ранее чем через 4 секунды.
3. При отдельном запуске не подавать поток после подсказки: через 10 секунд ожидается «БРАК / Нет реакции».
4. Сообщить читаемость скорости, результат и строку FLOW из Serial 115200. Если реакция не обнаружена, peak_pa поможет выбрать порог без догадок.
